# SEO process and analytics

Updated 2026-11-24. Production: https://air-alert-stat.com/.

The goal is that people (and search/AI assistants) who ask how many air raid alerts Kyiv or Kyiv Oblast had, for a day, month, year or since 2022, land on a page with the answer, the method and the sources. Everything below is either automated in this repository or an explicit manual step with an owner.

Add day or district pages only when Search Console shows real demand (section 6) and every page would carry unique, non-empty data.

## 2. Technical contract (enforced by tests)

- **One host, one URL per page.** Canonical host `air-alert-stat.com`, HTTPS, extensionless paths. Legacy `*.html` → 301 (`public/_redirects`). Worker routes redirect `www` → apex; static assets on `www` rely on canonical tags until the Cloudflare redirect rule (section 4) exists. Query strings on `/` are UI state; canonical stays `/`, and `robots.txt` disallows `/*?` because Google crawled ~850 such dashboard deep links within a day of launch (they compete with archive pages for crawl budget). Indexable pages never need a query string.
- **Real status codes.** Unknown URLs return 404 (`not_found_handling: "404-page"`); months before coverage or in the future return 404; `/progress` is served with `X-Robots-Tag: noindex`; `*.workers.dev` is `noindex`.
- **Every indexable page has:** one `<h1>`, a 20–110 character title, a 70–320 character description, self-canonical, reciprocal `hreflang` uk/en + `x-default`, Open Graph with `/og-image.png` (1200×630), JSON-LD (`Organization`, `WebSite`, `WebPage`, `BreadcrumbList`; `Dataset` on open-data pages). No keyword meta, no FAQ/rating/review markup that is not visible content.
- **Numbers are the dashboard's numbers.** Archive pages and CSV use `shared/seo-stats.mjs`, proven equal to `/api/range` (counts by start date, union of intervals split at Kyiv midnight). Unknown is never shown as zero: days before coverage are labelled, the method note states that a missing interval is not proof of no alert.
- **Safety invariants are unchanged.** No exact recent strike points, air-defence or critical-infrastructure locations on any page. Alerts and incidents stay separate datasets.
- **Discovery.** `robots.txt` → `/sitemap.xml` (Worker-generated, `lastmod` = latest stored alert row of the month, hreflang alternates). Changed URLs are submitted to IndexNow (Bing, Yandex, Seznam, Naver; key file `/a4556c5c8191c37591ebf699ba911c0f.txt`) once per Kyiv day from the minute cron at :41 UTC, retried hourly until it succeeds. Every attempt is stored in D1 `ingestion_state.seo_indexnow_last_attempt` (`status`, response excerpt or error); `seo_indexnow_submitted_on` holds the last successful day. Workers logs are not persisted for this Worker, so this record is the diagnostic. Google does not use IndexNow; it uses the sitemap.
- **Freshness/caching.** Archive HTML is edge-cached 30 min (current periods) or 6 h (past periods); CSV 3 h; sitemap 1 h. Bump `RENDER_VERSION` in `worker/seo.ts` whenever page templates change.
- **AI crawlers.** `robots.txt` allows all agents. Whether Cloudflare's AI-crawler blocking is on is an account setting; keep it off if answers in AI search (ChatGPT search, Perplexity, Google AI Overviews) are wanted. `/` and archive pages contain the answer in server HTML, so non-JS crawlers can quote it.

## 4. One-time account setup (owner; not doable from a PR)

1. **Google Search Console** — add a *Domain* property `air-alert-stat.com`; verify with the DNS TXT record in Cloudflare DNS (Search Console may offer automatic verification through Cloudflare). Submit `https://air-alert-stat.com/sitemap.xml`. Inspect `/`, `/stats/kyiv`, the latest month page and `/en/stats/kyiv`; request indexing.
2. **Bing Webmaster Tools** — import the site from Search Console (no extra verification), submit the sitemap. IndexNow then keeps Bing current (Bing's index is also used by DuckDuckGo, Yahoo and several AI search products).
3. **Cloudflare redirect rule** — Rules → Redirect Rules: `http.host eq "www.air-alert-stat.com"` → `concat("https://air-alert-stat.com", http.request.uri.path)`, preserve query, 301. Confirm "Always Use HTTPS" is on.
4. **Cloudflare AI-crawler setting** — check Security → Bots: decide whether AI crawlers may read the site (recommended: allow, see section 2).
5. **Cloudflare Web Analytics** — the beacon was observed on production on 2026-11-23; confirm the site appears in the dashboard and that Core Web Vitals are collected.

## 5. Operating cadence

**Weekly (Monday, ~15 min)**
- Read the `Production SEO audit` run; fix errors the same week.
- Search Console → Performance (last 7 vs previous 7 days): clicks, impressions, CTR, average position by query and page; Pages → indexing: new "Crawled/Discovered – currently not indexed", "Duplicate", "Soft 404" entries.
- Note new queries in the content backlog (section 6).

**Monthly (1st–3rd day)**
- The previous month's page becomes complete automatically; check it in URL Inspection and request indexing.
- Compare the month with the media's numbers when they publish them (Kyiv City Administration, Texty, Ekonomichna Pravda, Slovo i Dilo, Kyiv Independent…). Differences in method are explained on the page; differences in data are bugs.
- Optional distribution: post the month's headline numbers with the link (Telegram/X/Threads). This is the main source of natural links and branded searches.

**Quarterly**
- Titles/descriptions of the 10 pages with most impressions and CTR below the site median: rewrite in `shared/seo-pages.mjs`/`seo-static-pages.mjs`, bump `RENDER_VERSION`, compare CTR after 4 weeks.
- Core Web Vitals (Search Console + Cloudflare RUM, Speed → Real user monitoring, 30 days). Field data on 2026-11-27 (160 visits): LCP p75 608 ms (91% good), INP 82% good (worst element `#range-details .range-metrics`, 4.2 s, 10 samples), CLS 18% poor (0.52 on `html>body`, caused by removing the crawlable `#pre-render-content` after paint — fixed by removing it in a layout effect). The single 394 KB (gzip) bundle with MapLibre is not an LCP problem in the field; revisit code-splitting only if INP stays poor. Lab timings in the Claude in-app browser pane are throttled and not representative.
- Backlinks (Search Console → Links): who cites the data; reach out where data is quoted without a source link.

**Event-driven**
- Records (most alerts in a day, longest alert) update automatically on hub/year pages. When a record is broken, it is a good moment for outreach.
- Feb 24 anniversary and year end: year and hub pages already answer "how many alerts in year X / since the invasion"; make sure they are indexed beforehand.

## 7. Off-page (links and mentions)

- The open-data page and the "How to cite" block on every archive page are the link-earning assets. Point journalists and researchers there; never buy links.
- Keep the GitHub repository README linking to the site and the open-data page.
- Wikipedia: cite only where an article already discusses alert statistics and the page is a reliable source for that claim; do not add self-promotional links.

## 8. Changing SEO-relevant code

1. Edit `shared/seo-static-pages.mjs` → `npm run build:seo-pages` (tests fail on stale files). Edit archive templates in `shared/seo-pages.mjs` / `shared/seo-layout.mjs` → bump `RENDER_VERSION`.
2. `npm run test:seo && npm run test:seo-stats && npm run test:seo-worker`.
3. After deploy: run the `Production SEO audit` workflow manually and inspect one changed URL in Search Console.

## 9. Web analytics and the meaning of "unique visitors"

Cloudflare Web Analytics (privacy-first, no cookies) measures page views and visits of HTML loads; SPA view changes via `history.replaceState` are not separate page views. Cloudflare zone "unique visitors" includes bots and API clients and is directional only. Search Console counts search impressions and clicks, not users. Exact unique humans are not measurable without persistent identifiers and consent; do not report invented visitor numbers or guaranteed rankings.

| KPI | Source | Why |
| --- | --- | --- |
| Clicks, impressions, CTR, average position (by query/page/country/device) | Search Console, Bing Webmaster | search discovery |
| Indexed archive pages vs sitemap URLs | Search Console → Pages | technical health |
| Page views, visits, landing pages, referrers | Cloudflare Web Analytics | acquisition |
| LCP / INP / CLS (p75) | Cloudflare RUM, Search Console CWV | user experience |
| Referring domains | Search Console → Links | authority |
